한우리

학생의 독서 활동부터 센터의 수업 운영까지, 앱과 웹으로 잇는 학습 플랫폼을 설계했습니다.

역할
PM · 기획·디자인 리드
범위
학생·학부모·교사·센터 관리자·슈퍼관리자 · 앱·PC·모바일 웹
기간
2024.03 ~ 2025.12
결과
작성 예정

PROBLEM

학생의 연령별 독서 활동과 학부모·교사의 확인 업무, 센터·전체 운영을 함께 다뤄야 했습니다. 온라인 학습과 지역 센터 수업을 잇는 구조가 필요했습니다.

DECISION

학생·학부모·교사·센터 관리자·슈퍼관리자로 사용자를 나눴습니다. 연령에 맞춰 퀴즈 화면을 구분하고, 수업·레벨·보상 관리 항목을 메뉴 구조와 기능명세에 정리했습니다.

OUTCOME

관리자 메뉴 구조와 기능명세를 정리하고, 연령별 퀴즈와 학습 앱 화면을 디자인했습니다. 수업정보·레벨·보상부터 게시물·통계까지 관리자 화면으로 구체화했습니다.

PROCESS

01

IA · 기능명세

IA 최종(관리자 메뉴 Depth·화면·정보 정의)과 기능명세서(레벨별 정의).

02

연령별 디자인

필독도서퀴즈 화면을 연령별로 디자인(중등·고등·유초등).

03

와이어프레임

관리자(대시보드·수강생 상세·수업정보·퀴즈 입력·권한)와 앱(홈·퀴즈·온라인평가·보상·라운지) 와이어프레임.

04

퀴즈 디자인

퀴즈 풀이 → 객관식 → OX → 감정평가.

05

앱 디자인

수강생 홈, 필독도서퀴즈, 선긋기·온라인평가, 수업결과물, 보상, 라운지, 알림, 마이페이지.

06

관리자

대시보드, 수업정보, 레벨링, 추가 보상 설정, 배너, 앱 푸시 발송, 게시물, 통계.

셀트릭스 · 코리아벳랩

동물병원의 검사 의뢰부터 검사기관의 결과 보고서까지, 두 관리자의 업무를 잇는 서비스를 설계했습니다.

역할
PM · 기획·디자인 리드
범위
검사기관용 슈퍼관리자 · 동물병원용 관리자 · PC·모바일 웹
기간
2025.02 ~ 2025.10

PROBLEM

동물병원의 검사 의뢰와 검사기관의 접수·검사·보고서 업무를 이어야 했습니다. 같은 의뢰를 서로 다른 역할과 기기에서 확인할 수 있는 구조가 필요했습니다.

DECISION

검사기관용 슈퍼관리자와 동물병원용 관리자로 업무를 나눴습니다. 병원은 환자 정보와 검사 항목 입력에, 검사기관은 의뢰 처리와 보고서 작성에 맞춰 화면을 구성했습니다.

OUTCOME

메뉴 구조와 최종 기능 요구사항 문서를 정리하고, 검사기관·병원용 PC 화면을 디자인했습니다. 병원용 모바일 화면에는 검사 의뢰·내역 확인·키트 구매를 담았습니다.

PROCESS

01

메뉴 구조

초기 메뉴구조도(PRD 작성 전) → 2차.

02

PRD

관리자 어드민(SAC) 기능 요구사항 최종 확정본(노션).

03

흐름 설계

슈퍼관리자 어드민 흐름도.

04

컨셉

슈퍼관리자 컨셉 → 최종 확정 컨셉.

05

디자인 · PC

SAC 대시보드·워크리스트·검사 타입·보고서 생성, PAC 대시보드·의뢰 내역·의뢰 정보 확인·로그인.

06

디자인 · MO

대시보드, 검사 의뢰(환자 정보·검사 항목), 의뢰 내역, 키트 상품·상세, 로그인.

솔루엠 SOLNET

권한별로 고객·장치·콘텐츠를 관리하는 디지털 사이니지 콘솔을 설계했습니다.

역할
PM · 기획·디자인 리드
범위
슈퍼관리자·파트너·사용자 콘솔 · 장치·콘텐츠·라이선스 관리
기간
2024.02 ~

작성 예정

PROBLEM

슈퍼관리자·파트너·사용자가 서로 다른 권한으로 고객·장치·콘텐츠를 관리해야 했습니다. 계정 구조와 라이선스 조건을 반영한 콘솔 설계가 필요했습니다.

DECISION

계정과 메뉴 접근 범위를 권한별로 나누고, 고객·장치·콘텐츠·라이선스 업무를 구분했습니다. 섹션별 확정사항을 화면별 기능 정의와 관리 흐름에 반영했습니다.

OUTCOME

메뉴·계정·라이선스 기준을 기획 문서로 정리하고, 화면별 기능을 정의했습니다. 고객·장치·콘텐츠 목록부터 장치 상세·스케줄·라이선스까지 콘솔 화면을 디자인했습니다.

PROCESS

01

메뉴 구조

최초 메뉴구조도(SAC).

02

IA

3차 섹션별 기획 확정사항: 메뉴 확정 항목, 계정 구조, 라이선스.

03

흐름도

관리자 콘솔 흐름도.

04

기능 정의 · 와이어프레임

ASAC 포함 최종 기획: SAC·RMS·CMS 화면별 기능 정의와 2·3차 확정 사항.

05

콘솔 디자인

로그인, 고객 관리, 장치 관리(PAC), 콘텐츠 목록, 장치 상세·스케줄, 라이선스, 장치 관리(ASAC/RMS).

동서식품

커피머신 연결부터 취향에 맞는 추출과 사용 리포트까지 이어지는 앱을 설계했습니다.

역할
PM · 기획·디자인 리드
범위
모바일 앱 · 머신 연결·제어 · 커피 추출·사용 리포트

PROBLEM

커피머신의 첫 연결부터 추출과 사용 기록 확인까지 앱에서 이어져야 했습니다. 블루투스·Wi-Fi 연동 중 이탈을 줄이고, 선호 설정과 사용 리포트를 활용하도록 설계해야 했습니다.

DECISION

연동을 기기 검색·네트워크 선택·비밀번호 입력으로 나누고, 실패 안내와 성공 화면을 설계했습니다. 추출은 저장 설정을 쓰는 빠른 추출과 직접 설정하는 방식으로 구분했습니다.

OUTCOME

메뉴 구조와 와이어프레임을 정리하고, 머신 연동의 성공·실패 화면을 디자인했습니다. 메인·절전·커피 추출·완료 평가·사용 리포트·머신 관리 화면까지 구체화했습니다.

PROCESS

01

PRD

커피 머신 연동 앱 제품 요구사항 정의서: 목표·일정, 메뉴별 상세 기능.

02

와이어프레임

와이어프레임 전체: 홈, 연동/관리, 추출하기, 리포트, 더보기.

03

컨셉

4차 컨셉: 머신만 깔끔히 보이는 상단, 아이콘 동그라미 있는·없는 버전 비교.

04

머신 연동

연동 시작 → 블루투스·Wi-Fi 검색 → 목록 → 비밀번호, 연결 실패 안내와 연결 성공 화면.

05

디자인

전체 디자인: 메인·절전, 커피 추출(빠른·직접·완료 평가), 나의 커피 리포트, 머신 관리, 알림, 더보기.

아이포스처

AI 체형 분석과 회원 관리를 사용자 앱·센터·트레이너·통합 관리자 화면으로 설계했습니다.

상세보기
역할
PM · 기획·디자인 리드
범위
사용자 앱 · 센터 웹 · 트레이너 웹 · 통합 관리자
기간
운영 2024.04 ~ 2024.09 · 고도화 2025.01 ~ 2026.01
결과
작성 예정

PROBLEM

AI 체형 분석 결과를 확인하는 사용자와 상담·회원 관리를 맡는 센터·트레이너의 업무를 이어야 했습니다. 사용자 앱과 세 관리 화면 사이의 역할과 정보 흐름을 정리해야 했습니다.

DECISION

사용자 앱·센터 웹·트레이너 웹·통합 관리자로 접점을 나누고, 서비스 흐름을 연결했습니다. 신청서와 상담일지를 별도 문서로 구분해 작성·수정·공유 기준을 정리했습니다.

OUTCOME

네 접점의 서비스 흐름도와 사용자 앱 요구사항 문서를 정리했습니다. 센터·트레이너·통합 관리자 화면과 사용자 앱의 검사 리포트·식단 피드백·이용권 화면을 디자인했습니다.

PROCESS

01

흐름도

네 콘솔이 주고받는 서비스 흐름도(25-09판).

02

PRD

사용자 앱 요청사항 취합 PRD(노션): 구독 모델, 신청서·상담일지 기능.

03

센터 웹

센터 페이지 최종 디자인 전체.

04

트레이너 웹

트레이너 최종 시안: 로그인·회원가입, 대시보드, 회원 관리.

05

통합 관리자(SAC)

SAC 디자인과 수정 후 화면.

06

사용자 앱

최종 화면 전체: 홈, 전신기능검사 리포트, 식단 트레이너 피드백, 이용권.

카스파

세차장 키오스크 IoT 서비스와 세차 예약·이용권 구매 플랫폼을 함께 설계했습니다.

상세보기
역할
기획·디자인 1인 전담
범위
세차장 키오스크 · 사용자 앱 · 파트너·관리자 화면
기간
2023.09 ~ 2025.01
결과
고객 승인·납품 완료 · 앱 스토어 출시 · 실제 매장 운영

PROBLEM

고객사는 앱에서 세차 예약과 이용권 판매를 제공하려 했습니다. 매장 키오스크의 현장 이용과 앱의 사전 예약을 함께 설계하면서, 구매 방식과 선택 단계를 정리해야 했습니다.

DECISION

보유권 예약과 신규 1회권 구매를 별도 경로로 설계했습니다. 키오스크는 차량번호 자동 인식을 반영하고, 코스·차종·부착물 선택에서 결제로 이어지는 과정을 단순화했습니다.

OUTCOME

키오스크와 사용자 앱의 기획·디자인을 1인 전담해 고객 승인과 납품을 마쳤습니다. 앱 스토어 출시와 실제 매장 운영으로 이어져, 예약과 현장 세차에 쓰이는 서비스로 구현됐습니다.

PROCESS

01

흐름 설계

회원가입·로그인, 세차권 구매·예약, 차량 등록, 선물, 세차 진행·리뷰 흐름도.

02

와이어프레임

키오스크 회색조 레이아웃: 코스 선택 → 차종·부착물 → 옵션 → 주문 확인.

03

키오스크

키오스크 화면: 코스 선택, 주문 확인·결제, 결제 방식, 결제 완료, 차량번호 자동 인식.

04

앱 컨셉

메인 화면 대안 두 가지: 차량 상태를 먼저 보여 주는 안, 예약 현황을 먼저 보여 주는 안.

05

앱 디자인

사용자 앱 전체 흐름(메인 → 매장 → 예약 → 결제 → 고객센터 → 내 정보)과 주요 화면.

두잇

스마트 급식기·급수기 연결과 반려동물의 일상 관리를 한 앱으로 설계했습니다.

상세보기
역할
PM · 기획·디자인 리드
범위
급식기·급수기 연동 모바일 앱 · 반려동물 등록·리포트·건강 기록
기간
2025.01 ~ 2026.01
결과
작성 예정

PROBLEM

급식기와 급수기를 한 앱에 연결하고 반려동물의 일상 기록을 함께 다뤄야 했습니다. 기기 연결 상태와 네트워크·사료 인식 오류에 따라 서로 다른 화면과 안내가 필요했습니다.

DECISION

기기가 없을 때·일부 연결됐을 때·모두 연결됐을 때로 메인 화면을 나눴습니다. Wi-Fi 선택·DNS 설정·사료 인식 중 발생하는 오류를 구분해 안내 화면을 설계했습니다.

OUTCOME

메뉴 구조·기능명세·와이어프레임을 정리하고, 연결 상태별 메인 시안을 확정했습니다. 기기 연결·사료 인식 오류 안내와 반려동물 등록·리포트·건강 기록 화면을 디자인했습니다.

PROCESS

01

메뉴 구조

앱 메뉴구조도 ver.2.

02

기능명세 · 와이어프레임

기능명세서 와이어프레임 → 와이어프레임 1차 → 2차 기획(메인).

03

컨셉

메인 확정 시안: 기기 연결 후·기기 없음·모두 연결.

04

기기 연결

연결 시작 → Wi-Fi 선택 오류 → DNS 변경 오류.

05

사료 인식

사료 인식 준비, 움직임 감지 오류 안내. (재시도·인식 성공 화면은 미수집)

06

디자인
